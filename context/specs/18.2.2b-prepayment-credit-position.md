# 18.2.2b — Prepayment / Credit Position Rollup

## 1. Goal

Add a read-only National/Regional rollup report, slug `prepayment-credit-position`, that surfaces per-church `annualCredit` and `monthlyCredit` — the credit balance defined as `max(0, paid-to-date − expected-to-date)` per bucket — with scope totals and defunct churches visible and included. The unit adds no schema change, no migration, and keeps the build at 28/28 by adding one slug to the existing `[report]` dynamic route.

## 2. Design

### Concept definition

- **Credit position** in this report means the AR-side customer credit balance, not deferred revenue:
  - `annualCredit = getCreditBalance(annualPaid, expectedAnnual)`
  - `monthlyCredit = getCreditBalance(monthlyPaid, expectedMonthly)`
  - `getCreditBalance(paid, expected) = max(0, paid − expected)`
- This is the same definition already used on `app/dashboard/churches/[code]/page.tsx`.
- `prepaymentCredit` in Collections Summary (`allocation.billing_year > currentYear`) is a different concept: future-year allocation attribution / deferred-revenue view. The two reports are not expected to reconcile. This report must state that in plain English in the subtitle or a below-table footnote.
- Strict Bucket Isolation applies: Annual and Monthly credit are always separate columns and separate totals. There is no combined “Total Credit” column or KPI.

### Scope and visibility

- Registry entry uses `visibleTo: ['NATIONAL', 'REGIONAL']`.
- The `[report]` resolver already enforces visibility via `getReportsForRole(actorRole)`; Local roles receive `notFound()`.
- National scope: sees all churches in scope; region filter available via `getRegionOptions()`.
- Regional scope: sees only its region; region filter hidden because `regions.length === 0`.
- Local scope: not reachable through the route.

### Page layout

- Summary KPI row using the mandatory `<KpiGrid>` and `<KpiValue>` components:
  - Annual Credit total
  - Monthly Credit total
  - Churches with Annual Credit
  - Churches with Monthly Credit
- `<TableToolbar>`:
  - Title: “Prepayment / Credit Position”
  - Subtitle includes `scope_label`, `computed_at`, and the concept footnote.
  - Search: church code or church name.
  - Region filter: only when `regions.length > 0` (National).
  - Actions: `<PrintButton>` and `<ExportDropdown>`.
  - Bulk selection action: `<ExportDropdown>` for selected rows.
- `<TableShell>` table columns:
  1. Checkbox
  2. Church Code
  3. Church Name
  4. Region
  5. Annual Credit
  6. Monthly Credit
  7. Status
- Financial cells: `text-right font-medium tabular-nums`. Headers: `text-paragraph-small font-medium text-muted-foreground`. Row hover: `hover:bg-muted/50`.
- Footer totals:
  - Annual Credit total in its own cell.
  - Monthly Credit total in its own cell.
  - Defunct churches are included in footer totals (D1).
  - No combined total cell.
- Defunct rows appear with a `<Badge variant="outline">Defunct</Badge>`; they are visible, not filtered out.
- Pagination: 15 rows per page via `<DataTablePagination>`.
- Empty state: centered muted message, no CTA. Example: “No churches with credit balances in this scope.”
- No charts. This is a tabular rollup; do not add Recharts or any visualisation.

### Decisions recorded explicitly

- **D1 — Defunct included.** Defunct churches appear as rows with a badge, and their credit is included in footer totals. Rationale: credit is cash actually received and not yet offset by an obligation, not a notional write-off netting. This deliberately differs from Arrears Aging, whose footer excludes defunct because that report’s arithmetic is tied to write-off disclosure.
- **D2 — Visibility `['NATIONAL', 'REGIONAL']`.** A Local-scope rollup would be a single row and duplicate the church detail page’s existing credit display. The route resolver already enforces registry visibility.
- **D3 — No period parameter.** This is a stock report (current credit position), not a flow report. Both Annual and Monthly columns are always shown. Do not add a period toggle.

### Out of scope

- Deferred-revenue view / future-year attribution (`prepaymentCredit` in Collections Summary).
- Historical credit trend (would need schema and is not in this unit).
- Per-church drill-down (already lives on `app/dashboard/churches/[code]`).
- Refactoring `isChurchCompliant` internals or changing existing report definitions.
- Any schema change, migration, background task, SMS, audit-log write, or `prisma.$transaction`.

#### 1.1 `lib/utils/financial.ts`

Add under a clear `UNIT 18.2.2b` banner:

```ts
// ============================================================================
// UNIT 18.2.2b: CREDIT POSITION (single source of truth)
// ============================================================================

export type CreditPosition = {
  annualCredit: number
  monthlyCredit: number
  annualPaid: number
  monthlyPaid: number
  expectedAnnual: number
  expectedMonthly: number
}

/**
 * Prepayment / credit position per ledger for a church, as of `now`.
 *
 * Composes the existing single-source helpers:
 *  - `isChurchCompliant` — annualPaid / monthlyPaid / expectedAnnual / expectedMonthly
 *  - `getCreditBalance` — max(0, paid - expected)
 *
 * Strict Bucket Isolation: Annual and Monthly credit are independent.
 * There is no combined-credit concept. Do not re-derive this math in a report.
 */
export function getCreditPosition(
  church: Parameters<typeof isChurchCompliant>[0],
  now: Date = new Date()
): CreditPosition {
  const c = isChurchCompliant(church, now)
  return {
    annualCredit: getCreditBalance(c.annualPaid, c.expectedAnnual),
    monthlyCredit: getCreditBalance(c.monthlyPaid, c.expectedMonthly),
    annualPaid: c.annualPaid,
    monthlyPaid: c.monthlyPaid,
    expectedAnnual: c.expectedAnnual,
    expectedMonthly: c.expectedMonthly,
  }
}
```

Do not modify `isChurchCompliant` or `getCreditBalance`.

#### 2.1 `lib/actions/report-actions.ts`

Add exported types and server action following the 18.2.2a metadata-result convention:

```ts
export type CreditPositionRow = {
  church_id: string
  church_code: string
  church_name: string
  region_name: string
  is_defunct: boolean
  annual_credit: number
  monthly_credit: number
}

export type CreditPositionResult = {
  rows: CreditPositionRow[]
  scope_label: string
  computed_at: string
  total_annual_credit: number
  total_monthly_credit: number
  churches_with_annual_credit: number
  churches_with_monthly_credit: number
  churches_in_scope: number
}

export async function getPrepaymentCreditPosition(
  regionId?: string
): Promise<CreditPositionResult>
```

Implementation requirements:

- `'use server'`.
- Call `verifyReportsAccess()` at the top of the `try`.
- Scope with `buildChurchWhere(dbUser)`.
- For National roles only, merge `{ region_id: regionId }` into the church where-clause when `regionId` is provided. Do not add ad-hoc role checks elsewhere.
- Fetch churches with the minimum needed data: identity fields, `is_defunct`, `created_at`, region relation, and `payments` with `amount_paid`, `payment_type`, and `allocations` with `amount` and `allocation_type`. Mirror the query shape used by `getArrearsAgingReport`.
- For each church: `const credit = getCreditPosition(church, now)`.
- Build rows with `annual_credit` and `monthly_credit`.
- Compute totals over all rows in scope, including defunct churches:
  - `total_annual_credit`
  - `total_monthly_credit`
  - `churches_with_annual_credit` = rows with `annual_credit > 0`
  - `churches_with_monthly_credit` = rows with `monthly_credit > 0`
  - `churches_in_scope` = rows length
- `computed_at` = `now.toISOString()`.
- `scope_label` mirrors `getArrearsAgingReport`: “National”, region name, or church name.
- No period parameter.
- On `catch`: `console.error`, then return an empty `CreditPositionResult` with safe `scope_label`, `computed_at`, and zero totals. Do not change the house empty-result shape.
