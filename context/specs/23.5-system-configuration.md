# Unit 23.5: System Configuration

## Goal
Add a National-only **System** tab at `/dashboard/settings/system` that displays the project's fixed business-rule constants read-only and provides role-gated link-outs to the operational management surfaces that already exist. The page is an audit-facing reference: a read-only notice, a conditional environment banner, a print action that yields a clean audit pack, a provenance line (source file + deployed commit + change-history pointer), and no persistence, no schema change, no server actions.

## Design

### Placement & chrome
- Lives inside the existing settings surface (`app/dashboard/settings/layout.tsx`), inheriting the load-bearing inline wrapper `style={{ width: '100%', maxWidth: '64rem' }}` and the `@container` ancestor. **Preserve that inline style exactly** — it is the proven `<Card>` flex-collapse workaround (Unit 23 lesson).
- Page title/subtitle are provided by the settings layout; the System page renders no `<h1>` of its own.
- Content order: (1) read-only notice, (2) environment banner (conditional), (3) print action row, (4) 2×2 configuration card grid, (5) full-width Management Surfaces card, (6) provenance footer. Sections separated by `space-y-xl`; internal card spacing per `profile-card.tsx`.

### Page-level notice — read-only
- Always rendered at the top, full width: `flex items-start gap-3 rounded-xl border border-border bg-muted p-4`.
- Icon: Lucide `Info` at `h-4 w-4 text-muted-foreground` inside `rounded-md bg-background p-2 shrink-0`.
- Text: `text-paragraph-small font-medium text-foreground` headline "Read-only reference" plus `text-xs text-muted-foreground` line "These values are defined in application code and cannot be edited here. Changes are made via deployment."

### Page-level environment banner — conditional
Rendered when `bankAdapterMode` is `sandbox`, `live`, or unrecognized. Absent for `mock` and unset. Full width; same container shape as the notice:
- `live` → `bg-destructive/10 border border-destructive/20 text-destructive`, Lucide `AlertTriangle`, "PRODUCTION — Bank API calls target production. Real payments settle."
- `sandbox` → `bg-amber-500/10 border border-amber-500/20 text-amber-600`, Lucide `AlertTriangle`, "SANDBOX — Bank API calls target sandbox environments."
- unrecognized → `bg-amber-500/10 border border-amber-500/20 text-amber-600`, Lucide `AlertTriangle`, "UNRECOGNIZED MODE — verify BANK_ADAPTER_MODE."

`bankAdapterMode` is read server-side once in the page and passed to the content component; the banner and the Bank Integration card consume the same prop so they cannot disagree.

### Print action
- Right-aligned action row above the card grid: `flex justify-end print:hidden`.
- `<SystemPrintButton />` — a `'use client'` wrapper in `components/settings/system-print-button.tsx` rendering `<PrintButton onClick={() => window.print()} />`. `PrintButton` takes a client callback; the System page is a Server Component, so this wrapper is the single client island on the page. The shared `<PrintButton>` is reused; no styling is re-invented.
- Print polish (settings surface only): the tab strip, the print row, and the Management card carry `print:hidden`. The notice, environment banner (when present), configuration cards, and provenance footer print. Hiding global app chrome (sidebar/topbar) on print is cross-cutting and out of scope — logged as a papercut.
- Rationale: a configuration reference is the canonical print target for audit and board packs.

### Tab visibility (National-only)
- `app/dashboard/settings/layout.tsx` becomes `async`, exports `const instant = false` (see below), calls `await connection()`, resolves `const role = await getCurrentUserRole()`, and builds nav items: always `{ label: 'Profile', href: '/dashboard/settings/profile' }`; append `{ label: 'System', href: '/dashboard/settings/system' }` only when `isNationalLevel(role)`.
- **`export const instant = false` is required on the layout.** A layout cannot be wrapped in `<Suspense>` by its pages, and `await connection()` at the layout level triggers Next.js 16's Instant Navigations error on every child route (`/dashboard/settings/profile` throws without it). `instant = false` opts the entire settings segment out of prerendering — the same documented escape hatch already used on `/dashboard/reports/[report]` (Unit 18.2.2b). A blocking settings route is correct behaviour: the tab strip's shape depends on the authenticated role, so there is nothing honest to prerender.
- Subtitle updated to "Manage your personal profile and security, and view system configuration." (covers both tabs).
- `settings-nav.tsx` gains `print:hidden` on its `<nav>` only; it stays prop-driven with exact `pathname === href` matching.
- **Defence in depth:** the page re-checks `isNationalLevel(role)` server-side and `redirect('/dashboard/settings/profile')` otherwise. A hidden tab is UX; the redirect is the control.

### Section 1 — Configuration cards (2×2 grid)
`grid grid-cols-1 @[800px]:grid-cols-2 gap-md` (container queries, sidebar-aware). Each card follows `profile-card.tsx`: `<Card className="h-full w-full min-w-0">`, `CardHeader` with `CardTitle` at `text-heading-4 font-bold text-foreground` + `CardDescription`, `CardContent` with `space-y-6 min-w-0`.

`ConfigRow` helper mirrors the Email row of `profile-card.tsx` (the canonical, `min-w-0`-complete form): row `flex items-start gap-3 min-w-0`; icon `mt-0.5 rounded-md bg-muted p-2 shrink-0` (`h-4 w-4 text-muted-foreground`); text container `min-w-0`; label `text-paragraph-small font-medium text-foreground`; value `text-paragraph-small font-medium text-foreground tabular-nums`; helper `text-xs text-muted-foreground`.

**Card 1 — Financial Controls** (icon `ShieldCheck`)
| Row | Constant | Displayed as |
|---|---|---|
| Four-eyes threshold | `FOUR_EYES_THRESHOLD` | `formatCurrency` → KES 20,000 |
| Arrears critical window | `ARREARS_CRITICAL_DAYS` | "90 days" |
| Payment ceiling | `PAYMENT_INTENT_AMOUNT_CEILING` | `formatCurrency` → KES 500,000 |

**Card 2 — Operational SLAs** (icon `Timer`)
| Row | Constant | Displayed as |
|---|---|---|
| Reconciliation warning | `SLA_YELLOW_DAYS` | "7 days" (amber) |
| Reconciliation overdue | `SLA_RED_DAYS` | "30 days" (red) |
| Deletion warning | `CHURCH_DELETION_SLA_YELLOW_DAYS` | "3 days" (amber) |
| Deletion overdue | `CHURCH_DELETION_SLA_RED_DAYS` | "7 days" (red) |

**Card 3 — Payment System** (icon `CreditCard`)
| Row | Constant | Displayed as |
|---|---|---|
| Intent expiry | `PAYMENT_INTENT_EXPIRY_MINUTES` | "30 minutes" |

**Card 4 — Bank Integration** (icon `Landmark`)
- Consumes the same `bankAdapterMode` prop as the banner (read server-side; never `NEXT_PUBLIC_*`).
- Normalise: `mock` / `sandbox` / `live` recognised; any other non-empty string → unrecognized; empty/null → unconfigured.
- Badges use documented `ui-context.md` §2 pill palettes:
  - mock → N/A palette `bg-gray-100 text-gray-700 border-gray-200`, label "Mock"
  - sandbox → Partial/Pending palette `bg-amber-100 text-amber-700 border-amber-200`, label "Sandbox"
  - live → Overdue palette `bg-red-100 text-red-700 border-red-200`, label "Live (Production)"
  - unrecognized → Partial/Pending palette, label "Unrecognized: <value>" + `<InfoTooltip>`
  - unset → N/A palette, label "Not configured" + `<InfoTooltip>` (accepted values; flipping to live is out of scope)
- Helper text: mock "Bank API calls are simulated. No real money moves."; sandbox "Bank API calls target the sandbox environments."; live "Bank API calls target production. Real payments settle."; unrecognized "This value is not a recognised adapter mode. Verify BANK_ADAPTER_MODE."; unset "No adapter mode is configured."
- Live is deliberately red, matching the production banner — green is never used for the production mode.
- No credentials, keys, URLs, or secrets are ever displayed.

**Deliberately absent:**
- **Engineering internals** — `PRISMA_TRANSACTION_TIMEOUT`, `PAYMENT_INTENT_POLL_INTERVAL_MS`, `PAYMENT_INTENT_GRACE_SECONDS` are implementation knobs, not business rules.
- **Fee amounts (KES 500 / 5,000)** — not exported from `lib/constants.ts`; extraction is Unit 20.7. Card 1 is structured so 20.7 adds two rows without restructuring; a source comment (`{/* Fee amounts (KES 500 / 5,000) are added by Unit 20.7. Do not hardcode here. */}`) points to 20.7 inside `<CardContent>`.
- **Enforcement-point annotations** ("enforced in X") — valuable for auditors but a path-drift risk; the provenance footer names the source file. Deferred as a papercut.
- Constants imported directly from `lib/constants.ts` (server component) so the display cannot drift from the single source.

### Section 2 — Management Surfaces (full-width card)
A single `<Card>` (same pattern) with `grid grid-cols-1 @[600px]:grid-cols-2 @[900px]:grid-cols-3 gap-md`. Each entry is a `<Link>` wrapping `rounded-xl border border-border bg-card p-md transition-colors hover:bg-muted/50` with `focus-visible:outline-none focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2`, a Lucide icon (`h-5 w-5 text-primary`), title `text-paragraph-small font-semibold text-foreground`, one-line description `text-xs text-muted-foreground`, right-aligned `ChevronRight`.

Each link renders only when the sidebar shows the equivalent destination to that role — gates mirror `app-sidebar.tsx` exactly:

| Link-out | Destination | Rendered when | Description |
|---|---|---|---|
| Users | `/dashboard/users` | `isOperationsAdmin(role)` | "Manage user accounts and role assignments." |
| Regions | `/dashboard/regions` | `isNationalLevel(role)` | "View and manage regional oversight." |
| Churches | `/dashboard/churches` | `isNationalLevel(role)` | "View and manage church records." |
| Reconciliation | `/dashboard/reconciliation` | `isFinanceAdmin(role) \|\| isNationalTreasurer(role)` | "Resolve unmatched payments and review queues." |
| Reports | `/dashboard/reports` | `isNationalLevel(role)` | "Access the reports hub." |
| Audit Logs | `/dashboard/audit-logs` | `isNationalLevel(role)` | "Review the system activity trail." |

Result by role — Treasurer: Regions, Churches, Reconciliation, Reports, Audit Logs. System Admin: all six. Finance Admin: Regions, Churches, Reconciliation, Reports, Audit Logs. Operations Admin: Users, Regions, Churches, Reports, Audit Logs. National Overseer: Regions, Churches, Reports, Audit Logs.

The six link-outs are exactly the destinations enumerated in build plan 28.1. `app-sidebar.tsx` additionally renders two National destinations deliberately **not** duplicated here: **Deletion Requests** (Operations Admin / Treasurer / System Admin) and **Mock KCB** (Finance Admin / System Admin). Both are domain-specific operational tools — a queue surfaced by a sidebar badge and a development simulator — not the management surfaces 28.1 enumerates. "Mirrors 1:1" above describes gating, not card membership.

- If the list is empty (should not occur for any National role), the Management card is omitted.
- `<InfoTooltip>` on the card header explains these are shortcuts to existing management surfaces, permissions enforced server-side.
- Semantic wrapper: `<nav aria-label="Management surfaces">`.
- The Management card carries `print:hidden` (navigation, not audit content).

### Provenance footer
- Always rendered at the bottom: `text-xs text-muted-foreground`.
- Content: "Configuration source: `lib/constants.ts` · Deployed from `<short-sha>` · Change history is tracked in version control."
- `<short-sha>` = first 7 chars of `process.env.VERCEL_GIT_COMMIT_SHA ?? process.env.GIT_COMMIT_SHA ?? ''`; empty (local dev) renders "local development". Read server-side and passed as a prop.

### Accessibility & style conformance
- `<h2>` for each card title; links are real `<Link>` elements; `<nav>` wrapper for the management grid.
- Visible focus on every interactive element: `focus-visible:ring-2 focus-visible:ring-ring focus-visible:ring-offset-2`.
- Every KES figure uses `formatCurrency` from `lib/utils.ts` with `tabular-nums`; no inline `Intl.NumberFormat`.
- Tokens only — no hardcoded hex, no arbitrary spacing. Icons: `lucide-react`.
- No placeholder Tailwind syntax in this spec (Tailwind v4 scans `context/*.md` — Unit 23 lesson).
- All `<InfoTooltip>` content comes from `INFO_TOOLTIPS` in `lib/help/content.ts` under keys `bankAdapterMode` and `managementSurfaces`. Never inline tooltip strings — content is centralized (Unit 20 precedent).
