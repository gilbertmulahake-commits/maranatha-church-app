# Unit 18.1: Reporting Foundation & Core Reports

## Goal
Replace the current two-tab `/dashboard/reports` page with a hub-and-spoke reporting architecture. Fix the gross-arrears and Cheque-labelling bugs in the existing reports. Add three new reports: Write-Off Register, Defunct Church Register, and Inactive Church Report. All reports must be strictly bucket-isolated, write-off-aware, and gated by RBAC.

## Design

### Navigation & Layout
- **Hub Route:** `app/dashboard/reports/page.tsx` becomes a hub indexing all available reports, grouped by category (Financial, Reconciliation, Registry), mirroring the `/dashboard/reconciliation` hub layout.
- **Sub-routes:** `app/dashboard/reports/[report]/page.tsx` is a dynamic Server Component that fetches the specific report's data.
- **Report Shell:** A shared `components/reports/report-shell.tsx` wraps every report with a standard header (Title, description, scope) and a standardized `<TableToolbar>` + `<TableShell>` body.
- **Expected Page Count:** 27 → **28** (one dynamic route added). 

### Bucket Isolation & Write-Off Awareness
- Arrears and Write-Off reports must show **Gross**, **Less Written Off**, and **Net** columns for both Annual and Monthly buckets.
- Defunct churches must remain visible in the financial reports (Write-Off/Arrears) but carry a `<Badge>Defunct</Badge>`.
- Inactive churches are excluded from Arrears and Inactive reports if they are defunct.

## Implementation (including Dependencies)

### Dependencies
- **No new npm packages.**
- **Database Backfill:** Confirmed already applied in production (`source='Webhook'` for 18 records, `source='Manual'` for 2).
- **Deferred Pre-Launch (Do NOT implement in 18.1):** A `@@index([payment_date])` on the `Payment` model in `prisma/schema.prisma` will be required before onboarding 1,600 churches. Track for pre-launch DB migration.

### 1. Shared Infrastructure
- `lib/auth/guards.ts` — Add `verifyReportsAccess()`. It checks for authentication and a recognized role. Report-level scoping (National/Regional/Local) is handled by the query helper.
- `lib/utils/report-scope.ts` (new) — Export `buildReportWhere(dbUser)` to return the Prisma `where` fragment based on `dbUser.role` (`region_id` for regional, `id` for local, `{}` for national). 
- `components/reports/report-selector.tsx` (new) — A `<Select>` component to navigate between reports at the top of the hub/sub-routes.
- `components/reports/report-shell.tsx` (new) — Wraps title, description, and the table.

### 2. Fixes to Existing Reports
- `lib/actions/report-actions.ts` — 
  - Update `getArrearsReport()` to query `WriteOff` where `status='Approved'` and subtract them.
  - Return `grossAnnual`, `writtenOffAnnual`, `netAnnual` (and same for Monthly).
  - Append `is_defunct` to the `ArrearsRow` type.
- `components/reports/arrears-table.tsx` — 
  - Remove the local `formatCurrency` function. Import from `@/lib/utils`.
  - Add "Less WO" and "Net" columns for both buckets.
  - Add a `Defunct` badge next to the church name if `is_defunct` is true.
- `components/reports/cashbook-table.tsx` — 
  - Replace the inline `row.payment_method === 'M_Pesa' ? ... : ...` logic with `getReadableMethod(row.payment_method)` to fix the `Cheque` labelling bug in the table and modal.

### 3. New Server Actions & Reports
Add the following to `lib/actions/report-actions.ts` and create corresponding client tables:
- **Write-Off Register:** `getWriteOffRegister()`. Renders `components/reports/write-off-register-table.tsx`. Lists all approved write-offs (Church, Bucket, Amount, Reason, Date). 
- **Defunct Register:** `getDefunctChurchRegister()`. Renders `components/reports/defunct-register-table.tsx`. Lists churches where `is_defunct = true`, their total written-off, and date marked defunct.
- **Inactive Church Report:** `getInactiveChurches(months = 6)`. Renders `components/reports/inactive-churches-table.tsx`. 
  - *Logic:* Excludes defunct churches. Excludes churches with `created_at` < 6 months ago. Finds churches whose most recent `Payment` (status='Paid') is older than 6 months, OR have zero payments but were created > 6 months ago.
