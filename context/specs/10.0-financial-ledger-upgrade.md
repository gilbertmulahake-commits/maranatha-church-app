# Unit 10.0: Financial Ledger Upgrade (Pre-requisite for Payments Tab)

## Goal
Upgrade the financial architecture to properly handle year-end carry-forwards (arrears rolling from one year to the next). This fixes the critical silent revenue leakage where year-end arrears vanish on Jan 1st, and unlocks the Month/Year view toggle for the data tables. 

By shifting from a "resetting" annual calculation to a cumulative lifetime calculation, the system accurately reflects what a church *should* have paid since the day they registered, minus what they *actually* paid.

## Design
- **Schema Change:** Add `billing_year Int` to the `Payment` model to explicitly track which year a payment was intended for, preventing cross-year confusion.
- **Logic Change:** The "Expected to Date" calculation shifts from a "reset on Jan 1" model to a cumulative model. We introduced `getExpectedUpToDate(startDate, upToDate)` which loops through every year from the church's `created_at` date to the current date.
- **UI Change:** The `TableToolbar` will activate the Month/Year toggle. When "Monthly" is selected, the table shows monthly payments and monthly outstanding. When "Yearly" is selected, it shows annual payments and annual outstanding. 
- **Next.js 16 Fix:** Abandon the deprecated `export const instant = false` approach and implement a universal `<Suspense>` + `await connection()` wrapper for all authenticated routes to fix `cacheComponents` prerender errors.

### 2. Financial Logic Update (`lib/utils/financial.ts`)
- [x] Deprecated `getExpectedToDate(upToDate)`.
- [x] Created `getExpectedUpToDate(startDate: Date, upToDate: Date = new Date())`. 
  - *Mechanic:* Iterates from `startDate.getFullYear()` to `upToDate.getFullYear()`. 
  - *Annual Logic:* Adds KES 5,000 if the year is in the past, or if it's the current year and the date is past March 31st.
  - *Monthly Logic:* Calculates the exact number of months elapsed between `startDate` and `upToDate`, multiplying by KES 500.
- [x] Added `getPeriodStatus(paid, expected)` to evaluate specific buckets (returns 'Paid', 'Partial', or 'Overdue').
- [x] Added `getCreditBalance(totalPaid, expectedToDate)` to safely calculate overpayments (`Math.max(0, paid - expected)`).
