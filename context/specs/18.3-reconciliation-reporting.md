# Unit 18.3: Reconciliation Reporting — Payment Intake Health

## Goal

Add three read-only National-only reconciliation health reports — `payment-intake-volume`, `payment-unmatched-backlog`, `payment-sla-aging` — that surface webhook flow, current unresolved backlog, and historical resolution SLA. The unit adds no schema change beyond three preventive indexes on `UnmatchedPayment`, and keeps the build at 28/28 (three new slugs on the existing `[report]` route).

## Design

### Concept definitions

Three reports, three different questions, three different measurement bases. They are **not** expected to reconcile — this is deliberate and matches enterprise reconciliation ops practice.

- **Intake Volume — flow, by arrival date.** "How many webhooks arrived, and how many matched?" Measures the raw inflow of payment events. A webhook that arrives in January and is resolved in March counts as January volume (arrival) plus March resolution (throughput), not double-counted in either report.
- **Unmatched Backlog — current state, as of now.** "What is stuck in the queue right now, and how old is it?" Point-in-time snapshot, not a period flow. Includes KES value at risk, per-bucket count and value, and the oldest single item.
- **SLA Aging — throughput, by resolution date.** "Of the items actioned in the last N days, how many were resolved within our 72h target?" Historical quality metric. SLA clock = `reviewed_at − created_at`.

### Metric definitions (must match exactly in code)

- **Total webhooks received (period)** = `COUNT(UnmatchedPayment WHERE created_at IN period) + COUNT(Payment WHERE source='Webhook' AND payment_date IN period)`
- **Straight-Through Rate (STR)** = `COUNT(Payment WHERE source='Webhook') / Total webhooks received` — measures auto-match success
- **Manual Intervention Rate** = `COUNT(Payment WHERE source='Resolved') / Total webhooks received` — measures how often humans had to step in
- **Rejection Rate** = `COUNT(UnmatchedPayment WHERE status='Rejected') / Total webhooks received` — measures upstream data quality (wrong BillRefNumbers, wrong payer)
- **Match Rate** = `1 − (Captured / Total received)` where Captured = `COUNT(UnmatchedPayment WHERE created_at IN period)`
- **Current Backlog** = `COUNT(UnmatchedPayment WHERE status='Pending')` — right now, no period filter
- **Backlog KES** = `SUM(UnmatchedPayment.amount WHERE status='Pending')`
- **SLA Met** = `COUNT(UnmatchedPayment WHERE reviewed_at IN period AND status IN ('Resolved','Rejected','WrittenOff') AND (reviewed_at - created_at) <= 72h)` — a rejected item still counts as "actioned within SLA" (rejection is a resolution, just a negative outcome)
- **SLA Met %** = `SLA Met / total actioned in period`

### Scope and visibility

- Registry entries use `visibleTo: ['NATIONAL']`. Regional and Local roles see 404 on the route (resolver enforces via `getReportsForRole`).
- Registry `group: 'Reconciliation'`.
- No region filter — National-only scope means no narrowing is meaningful. Reports cover the entire national registry.
- No period-level narrowing beyond the period toggle itself.

### Page layout — Report 1: `payment-intake-volume`

- Period toggle: 7 / 30 / 90 / All Time (4 options, mobile `<Select>`, desktop `<Button>` group — mirrors the period toggle pattern used on Collections Summary).
- `<KpiGrid>` with 4 cards:
  1. **Total Webhooks** — count
  2. **Total KES Received** — `formatCurrency` value
  3. **Straight-Through Rate** — %
  4. **Manual Intervention Rate** — %
- **Bar chart** above the table (Recharts). Two stacked series: `matched` (CSS var `var(--color-emerald-500)`), `unmatched captured` (CSS var `var(--color-amber-500)`). `<CartesianGrid vertical={false} />`. Bars `radius={[4, 4, 0, 0]}`. Custom `<ChartTooltip>`. Y-axis count, X-axis date.
- `<TableShell>` columns: Checkbox | Date | Total | Matched (STP) | Resolved Later | Captured (Unmatched) | Match Rate % | KES Received
- Footer: period totals, match rate %, KES total.
- Empty state: centered muted icon (`Inbox`), muted message "No webhook activity in the selected period.", no CTA.

### Page layout — Report 2: `payment-unmatched-backlog`

- **No period toggle.** Header states "As of {computed_at}". This is a current-state report.
- `<KpiGrid>` with 4 cards:
  1. **Current Backlog** — count
  2. **Backlog Value (KES)** — `formatCurrency`
  3. **Oldest Item** — age in days (red if >72h)
  4. **Breached >72h** — count
- `<TableShell>` columns: Checkbox | Age Bucket | Count | KES Value | % of Backlog | Oldest Item in Bucket
- Rows: 4 fixed buckets (0–24h, 24–48h, 48–72h, 72h+). Empty buckets shown as zero rows (do not hide — the presence of a clean 0 in 72h+ is itself informative).
- `<ExportDropdown>` + `<PrintButton>`.
- Below-table `<Badge>` block: "Oldest unresolved: {code} — {days}d" as a single escalation banner.
- Empty state: centered muted icon (`CheckCircle2`), muted message "No unmatched payments in the backlog — the queue is clear.", no CTA.

### Page layout — Report 3: `payment-sla-aging`

- Period toggle: 7 / 30 / 90 / All Time.
- `<KpiGrid>` with 4 cards:
  1. **Items Actioned** — count of resolutions in period
  2. **SLA Met %** — % within 72h target
  3. **Avg Resolution Time** — hours (formatted e.g. `18.4h`)
  4. **Breached Count** — count, red if >0
- `<TableShell>` columns: Checkbox | Age Bucket | Resolved | Rejected | Written Off | Total Actioned | Avg Time in Bucket | SLA Met?
- Rows: same 4 buckets. "SLA Met?" column uses the `<SlaBadge>` component from `components/reconciliation/sla-badge.tsx` if its API accepts an hours number; otherwise a `<Badge>` with the appropriate semantic color classes from `ui-context.md`.
- Footer: aggregate totals + overall SLA Met %.
- Empty state: centered muted icon (`Inbox`), muted message "No items actioned in the selected period.", no CTA.

### Decisions recorded explicitly

- **D1 — Three separate reports, not one composite.** Matches the 18.2 one-table-per-report pattern. Each report owns one question.
- **D2 — NATIONAL-only visibility.** Webhook infrastructure health is National HQ finance. Regional chairmen don't need bank API match rates.
- **D3 — 72h SLA target, 4 age buckets.** Matches standard fintech reconciliation SLAs and the existing `<SlaBadge>` component in `components/reconciliation/`.
- **D4 — Rejection counts toward SLA met.** A rejected item still required human action within the SLA window. Rejection is a quality signal, not an SLA failure. Rejected items appear in their own column on the SLA table.
- **D5 — Reports do not reconcile to each other.** Volume is by arrival; SLA is by resolution; backlog is current state. Webhooks arriving in March may be resolved in April; the two will always show different period totals. This is correct.
- **D6 — No region filter.** National-only scope. Adding a region filter would require joining `UnmatchedPayment → Church` on the assigned_church_id, but that's null for `Pending` items — the concept doesn't map. Report is national by design.
- **D7 — Preventive indexes on `UnmatchedPayment`.** Two new indexes: `@@index([created_at])` and `@@index([reviewed_at])`. The first supports period range scans on arrival date; the second supports period range scans on resolution date. **Discovery during implementation:** `@@index([status, created_at])` was already added in Unit 17 alongside `raw_bill_ref` and `assigned_church_id` — no duplicate needed. One migration adds the two missing indexes. **No schema model change** — indexes only.

### Out of scope

- Any new schema model or field (indexes only, per D7).
- Email / SMS alerts on backlog breaches.
- Automated anomaly detection (charts surface anomalies visually; no programmatic flagging).
- Cross-report reconciliation logic.
- Payment Intake Health on the Executive Command Center dashboard (candidate for a future unit, not this one).
- Deep-link from backlog bucket row → reconciliation queue (would require query-param handling on `/dashboard/reconciliation/unmatched`; candidate for a later unit).

### Part 2 — Server actions

**File: `lib/actions/report-actions.ts`**

Add three server actions. Each calls `verifyReportsAccess()` at the top of `try`, and adds an explicit inline role check (matching the `getRegionOptions` pattern) to enforce NATIONAL-only:

```ts
const { dbUser } = await verifyReportsAccess()
if (!isNationalLevel(dbUser.role)) throw new Error('Forbidden')
```

*Note: This is consistent with `code-standards.md` § RBAC Guard Pattern, which requires `verifyReportsAccess()` for all report reads and does not introduce a new guard helper.*

**Return-shape note:** These three actions return metadata-rich result types (`IntakeVolumeResult`, `UnmatchedBacklogResult`, `SlaAgingResult`) rather than the `Promise<TypedRow[]>` shape from `code-standards.md` § Reporting Patterns. This follows the 18.2.2a/18.2.2b precedent (Arrears Aging and Prepayment use analogous wrapper types) because these reports need `computed_at`, `period_label`, and pre-computed totals to render header/banner/footer without recomputing client-side.

**`getPaymentIntakeVolume(periodDays: number | 'all')`** — returns:

```ts
export type IntakeVolumeRow = {
  date: string                  // 'YYYY-MM-DD'
  total_webhooks: number
  matched_stp: number           // source='Webhook'
  resolved_later: number        // source='Resolved'
  captured_unmatched: number    // UnmatchedPayment created
  match_rate_pct: number
  kes_received: number
}

export type IntakeVolumeResult = {
  rows: IntakeVolumeRow[]
  period_label: string
  computed_at: string
  totals: {
    total_webhooks: number
    matched_stp: number
    resolved_later: number
    captured_unmatched: number
    match_rate_pct: number
    straight_through_rate_pct: number
    manual_intervention_rate_pct: number
    rejection_rate_pct: number
    kes_received: number
  }
}
```

Implementation: two grouped Prisma queries (Payments grouped by date, UnmatchedPayment grouped by date), merged in-app by date key. Period filter on `created_at` (unmatched) and `payment_date` (payments). When `periodDays === 'all'`, skip the filter.

**`getUnmatchedBacklog()`** — returns:

```ts
export type BacklogBucket = {
  bucket_key: '0-24h' | '24-48h' | '48-72h' | '72h+'
  label: string
  count: number
  kes_value: number
  pct_of_backlog: number
  oldest_item_age_hours: number
}

export type UnmatchedBacklogResult = {
  buckets: BacklogBucket[]
  computed_at: string
  totals: {
    count: number
    kes_value: number
    oldest_item_age_hours: number
    breached_72h_count: number
  }
  oldest_item: { bank_reference: string; age_hours: number } | null
}
```

Implementation: `prisma.unmatchedPayment.findMany({ where: { status: 'Pending' }, select: { created_at: true, amount: true, bank_reference: true } })`. Compute buckets in-app.

**`getSlaAging(periodDays: number | 'all')`** — returns:

```ts
export type SlaBucket = {
  bucket_key: '0-24h' | '24-48h' | '48-72h' | '72h+'
  label: string
  resolved: number
  rejected: number
  written_off: number
  total_actioned: number
  avg_time_hours: number
  sla_met: boolean
}

export type SlaAgingResult = {
  buckets: SlaBucket[]
  period_label: string
  computed_at: string
  totals: {
    items_actioned: number
    sla_met_pct: number
    avg_resolution_hours: number
    breached_count: number
    kes_resolved: number
  }
}
```

Implementation: `prisma.unmatchedPayment.findMany({ where: { status: { in: ['Resolved','Rejected','WrittenOff'] }, reviewed_at: { gte: periodStart } }, select: { created_at: true, reviewed_at: true, status: true, amount: true } })`. Bucket by `(reviewed_at − created_at)`.

**Time utility** — small in-file helper `hoursBetween(a: Date, b: Date): number`. Do not inline Date math across all three actions; extract once.

`Period` is `7 | 30 | 90 | 'all'`. Convert to `periodStart: Date | null` in one helper. `computed_at = new Date().toISOString()`.
