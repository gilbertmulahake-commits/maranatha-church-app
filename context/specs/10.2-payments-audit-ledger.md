# Unit 10.2: Payments Tab (Audit Ledger)

## Goal
Build a comprehensive, transaction-level ledger for auditing all incoming payments. This tab must allow the National HQ and Regional Chairmen to search, filter, and verify every single shilling that enters the KCB account. 

## Design
- **Layout:** Uses the existing `AppShell`. The page will feature a 4-card KPI row at the top, followed by the standard `TableToolbar` and Data Table.
- **KPI Cards:**
  1. **Total Transactions:** Count of payments (with a breakdown of M-Pesa vs Bank).
  2. **Total Volume:** Sum of all payments (KES).
  3. **Annual vs Monthly:** Stacked bar showing the total volume split by payment type.
  4. **This Month:** Volume collected in the current calendar month.
- **Data Table Columns:**
  - `Transaction ID` (Mono font)
  - `Church` (Name + Code)
  - `Amount` (KES, tabular-nums)
  - `Type` (Annual/Monthly badge)
  - `Method` (M-Pesa, KCB, Cash)
  - `Date` (Formatted)
  - `Status` (Paid, Pending)
- **Filters:** 
  - Global search (Search by Transaction ID, Church Code, or Phone).
  - Payment Type (All, Annual, Monthly).
  - Payment Method (All, M-Pesa, Bank, Cash).
- **Role Isolation:** 
  - National sees all payments.
  - Regional Chairman only sees payments for churches in their region (Enforced by backend action).

## Implementation
### 1. Server Action (`lib/actions/payment-actions.ts`)
- Create `getPayments()` action.
- Fetch from `prisma.payment.findMany()`, including the related `Church`.
- Calculate the KPI stats (Total Volume, Split by Type, Split by Method) within this action.

### 2. Page & UI
- Update `app/dashboard/payments/page.tsx` (Wrap in Suspense + connection).
- Create `components/payments/payments-kpi-cards.tsx`.
- Create `components/payments/payments-table.tsx` (Client component with sorting, pagination, and search).
- Create `components/payments/view-receipt-dialog.tsx` (Optional: to view exact raw payload data if stored).
