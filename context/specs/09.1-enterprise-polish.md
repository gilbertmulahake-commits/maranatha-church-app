# Unit 09.1: Enterprise Consistency & Polish

## Goal
Elevate the entire application to production-grade, enterprise-level consistency. This unit serves as a "correction and polish" phase that closes all gaps identified during the Unit 09 rollout. It ensures:
1. Global themeability (no hardcoded hex colors).
2. Full CRUD functionality across all tables (Regions and Churches).
3. Complete cross-filtering (drill-downs).
4. Uniform shadcn "Dashboard 1" patterns for KPI cards and Data Tables.

## Design
- **No Hardcoded Hexes:** All components must use semantic tokens (`bg-primary`, `bg-sidebar`, `text-muted-foreground`, `border-border`) defined in `globals.css`.
- **shadcn Table Standard:** All tables must use `<Table>`, `<TableHead>`, `<TableRow>`, `<TableCell>` from shadcn/ui, never raw HTML `<table>`.
- **shadcn Card Standard:** All KPI cards must use `<Card>`, `<CardHeader>`, `<CardTitle>`, `<CardAction>`, `<CardFooter>`, with `@container/card` for responsiveness.
- **Dialog Standard (Base UI):** Dialogs (View/Edit/Delete) must be controlled at the parent level (not nested inside Dropdown Menu items) to prevent the "flash and disappear" bug.
- **Cross-Filtering:** Clicking "View Churches" on a Region must navigate to `/dashboard/churches?region=X` with the filter applied.
