# Unit 15.6: SYSTEM_ADMIN Role & Protected User Accounts

## Goal
Add a `SYSTEM_ADMIN` role to securely preserve vendor/platform owner access post-handover. Ensure this role has full system capabilities but cannot be deleted, deactivated, or have its role changed by any client user (including `NATIONAL_TREASURER`) via the UI. It must also be hidden from the standard Users list.

## Design
- **RBAC Updates:** `SYSTEM_ADMIN` must be treated as a superset of `NATIONAL_TREASURER`. Anywhere the code checks for `role === 'NATIONAL_TREASURER'`, it must also check for `role === 'SYSTEM_ADMIN'`.
- **Protection:** A hardcoded allowlist of UUIDs (`lib/auth/protected-users.ts`) will identify SYSTEM_ADMIN accounts. Server actions mutating users will check this list and return a 403 error if a protected ID is targeted.
- **Visibility:** The `/dashboard/users` table will filter out protected users unless the requesting viewer is also a SYSTEM_ADMIN.

## Implementation

### Dependencies
- None (native Prisma & Next.js).

### 1. Prisma Schema Update
- Update the `Role` enum in `prisma/schema.prisma`. Add `SYSTEM_ADMIN` as the first value so it sorts to the top in the UI dropdowns.
  ```prisma
  enum Role {
    SYSTEM_ADMIN
    NATIONAL_TREASURER
    NATIONAL_OVERSEER
    REGIONAL_CHAIRMAN
    REGIONAL_TREASURER
    LOCAL_PASTOR
    CHURCH_TREASURER
  }
  ```
- Run the migration: `npx prisma7 migrate dev --name add_system_admin_role`

### 2. Create Protected Users Helper (`lib/auth/protected-users.ts`)
- Create a new file to house the hardcoded allowlist and a helper function.
  ```typescript
  export const PROTECTED_USER_IDS: string[] = [
    // Vendor UUIDs will be pasted here post-deployment
  ]

  export function isProtectedUser(userId: string): boolean {
    return PROTECTED_USER_IDS.includes(userId)
  }
  ```

### 3. Enforce Protection in Server Actions (`lib/actions/user-actions.ts`)
- Import `isProtectedUser` from `@/lib/auth/protected-users`.
- In `deleteUser`, `updateUserRole`, and `deactivateUser`:
  - Add a guard clause at the very top of the function: `if (isProtectedUser(targetUserId)) throw new Error("Cannot modify a protected system account.")`
- In `getSystemUsers`:
  - Check the role of the user making the request (the viewer).
  - If the viewer is NOT `SYSTEM_ADMIN`, filter the returned user array to exclude any user whose ID is in `PROTECTED_USER_IDS`.

### 4. Update Routing & Navigation (`proxy.ts` & `components/layout/app-sidebar.tsx`)
- **`proxy.ts`**: Audit all route protection rules. Anywhere `role === 'NATIONAL_TREASURER'` is allowed, add `|| role === 'SYSTEM_ADMIN'`.
- **`components/layout/app-sidebar.tsx`**: Update the role checks for rendering navigation items. The `SYSTEM_ADMIN` role should receive the exact same navigation array as `NATIONAL_TREASURER` (including Dashboard, Regions, Churches, Payments, Users, Mock KCB, Reports, Settings).

### 5. UI Defense in Depth (`components/users/users-table.tsx`)
- Pass the current viewer's role into the table component.
- If a row represents a protected user (check against `PROTECTED_USER_IDS`) AND the viewer is not a `SYSTEM_ADMIN`:
  - Hide the "Delete" and "Deactivate" buttons from the dropdown menu.
  *(Note: The server action already enforces this, but hiding the buttons prevents UI confusion).*
